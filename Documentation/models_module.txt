# Документация модуля models

## Описание

Модуль `models` содержит определения моделей данных, представляющих сущности приложения для работы с базой данных. Модели определяют структуру таблиц базы данных и отношения между ними с использованием SQLAlchemy ORM.

## Основные модели

### 1. User (Пользователь)

**Таблица**: `users`

**Назначение**: Хранение информации о пользователях системы.

**Ключевые поля**:
- `id`: Первичный ключ
- `email`: Электронная почта (уникальная)
- `name`: Имя пользователя
- `hashed_password`: Хэшированный пароль
- `is_active`: Статус активности пользователя
- `is_superuser`: Флаг суперпользователя (админ)
- `created_at`: Дата создания
- `updated_at`: Дата обновления

**Отношения**:
- `topics`: Темы, на которые подписан пользователь (many-to-many)
- `digests`: Дайджесты, созданные для пользователя (one-to-many)

### 2. Topic (Тема)

**Таблица**: `topics`

**Назначение**: Представляет тематические категории для новостей.

**Ключевые поля**:
- `id`: Первичный ключ
- `name`: Название темы (уникальное)
- `description`: Описание темы
- `created_at`: Дата создания
- `category`: Категория темы

**Отношения**:
- `users`: Пользователи, подписанные на тему (many-to-many)
- `articles`: Статьи, относящиеся к данной теме (one-to-many)

### 3. Article (Статья)

**Таблица**: `articles`

**Назначение**: Хранение новостных статей, собранных из различных источников.

**Ключевые поля**:
- `id`: Первичный ключ
- `title`: Заголовок статьи
- `content`: Содержание статьи
- `url`: URL источника (уникальный)
- `source`: Название источника
- `published_at`: Дата публикации
- `created_at`: Дата добавления в систему
- `topic_id`: Связь с темой
- `sentiment_score`: Оценка тональности (от NLP-анализа)
- `sentiment_details`: Детали анализа тональности (JSON)
- `keywords`: Ключевые слова (JSON)
- `entities`: Именованные сущности (JSON)
- `key_phrases`: Ключевые фразы (JSON)
- `summary`: Автоматически сгенерированное резюме статьи

**Отношения**:
- `topic`: Тема, к которой относится статья (many-to-one)
- `digest_articles`: Связи с дайджестами (one-to-many)

### 4. Digest (Дайджест)

**Таблица**: `digests`

**Назначение**: Представляет собой сборник новостей для конкретного пользователя.

**Ключевые поля**:
- `id`: Первичный ключ
- `user_id`: Связь с пользователем
- `title`: Заголовок дайджеста
- `created_at`: Дата создания
- `is_read`: Флаг прочтения

**Отношения**:
- `user`: Пользователь, для которого создан дайджест (many-to-one)
- `articles`: Связи со статьями через промежуточную таблицу (many-to-many)

### 5. DigestArticle (Статья в дайджесте)

**Таблица**: `digest_articles`

**Назначение**: Промежуточная таблица для связи дайджестов и статей.

**Ключевые поля**:
- `id`: Первичный ключ
- `digest_id`: Связь с дайджестом
- `article_id`: Связь со статьей
- `topic_id`: Связь с темой (опционально)
- `order`: Порядок статьи в дайджесте
- `created_at`: Дата создания связи

**Отношения**:
- `digest`: Дайджест (many-to-one)
- `article`: Статья (many-to-one)
- `topic`: Тема (many-to-one)

### 6. NewsSource (Источник новостей)

**Таблица**: `news_sources`

**Назначение**: Хранение информации об источниках новостей и их конфигурации для скрапинга.

**Ключевые поля**:
- `id`: Первичный ключ
- `key`: Уникальный ключ источника
- `name`: Название источника
- `url`: URL источника
- `article_selector`: CSS-селектор для обнаружения статей
- `title_selector`: CSS-селектор для извлечения заголовка
- `content_selector`: CSS-селектор для извлечения содержания
- `date_selector`: CSS-селектор для извлечения даты (опционально)
- `date_format`: Формат даты (опционально)
- `fallback_article_selector`: Резервный селектор для статей (опционально)
- `fallback_content_selector`: Резервный селектор для содержания (опционально)
- `created_at`: Дата создания
- `updated_at`: Дата обновления
- `is_active`: Флаг активности источника

## Отношения между моделями

1. **User ↔ Topic**: Отношение многие-ко-многим через промежуточную таблицу `user_topics`
2. **User ← Digest**: Отношение один-ко-многим (у пользователя может быть много дайджестов)
3. **Topic ← Article**: Отношение один-ко-многим (тема может содержать много статей)
4. **Article ↔ Digest**: Отношение многие-ко-многим через таблицу `digest_articles`

## Примечания по использованию

1. **Доступ к моделям**:
   ```python
   from app.models.models import User, Topic, Article, Digest, DigestArticle, NewsSource
   ```

2. **Обязательные поля**:
   - Для `User`: `email`, `hashed_password`
   - Для `Topic`: `name`
   - Для `Article`: `title`, `url`, `topic_id`
   - Для `Digest`: `user_id`
   - Для `DigestArticle`: `digest_id`, `article_id`
   - Для `NewsSource`: `key`, `name`, `url`, `article_selector`, `title_selector`, `content_selector`

3. **NLP-поля статей** (`sentiment_score`, `keywords`, и т.д.) могут быть пустыми, если анализ не был проведен

4. **Работа с JSON-полями**:
   ```python
   # Сохранение JSON-данных
   article.keywords = json.dumps(["news", "politics", "economy"])
   
   # Чтение JSON-данных
   keywords = json.loads(article.keywords) if article.keywords else []
   ```
