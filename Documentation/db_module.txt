# Документация модуля db

## Описание

Модуль `db` отвечает за взаимодействие с базой данных и управление сессиями базы данных в приложении. Он предоставляет абстракцию для работы с базой данных через SQLAlchemy ORM, реализует создание таблиц и содержит инструменты для инициализации базы данных.

## Структура модуля

### 1. session.py

**Назначение**: Управление сессиями базы данных.

**Функциональность**:
- Создание и конфигурирование движка базы данных (SQLAlchemy engine)
- Создание фабрики сессий для работы с базой данных
- Предоставление функции-зависимости `get_db()` для получения сессии базы данных в эндпоинтах FastAPI

**Ключевые функции**:
- `get_db()` - зависимость FastAPI для получения сессии БД

**Как использовать**:
```python
from fastapi import Depends
from app.db.session import get_db
from sqlalchemy.orm import Session

@app.get("/items/")
def read_items(db: Session = Depends(get_db)):
    # Используем сессию для запросов к БД
    items = db.query(Item).all()
    return items
```

### 2. base_class.py

**Назначение**: Определение базового класса для моделей SQLAlchemy.

**Функциональность**:
- Реализует базовый класс `Base` для всех моделей
- Настраивает метаданные SQLAlchemy
- Обеспечивает единый интерфейс для всех моделей в приложении

**Как использовать**:
```python
from app.db.base_class import Base
from sqlalchemy import Column, Integer, String

class MyModel(Base):
    __tablename__ = "my_models"
    
    id = Column(Integer, primary_key=True, index=True)
    name = Column(String)
```

### 3. create_tables.py

**Назначение**: Создание таблиц в базе данных при запуске приложения.

**Функциональность**:
- Импортирует все модели для регистрации в метаданных SQLAlchemy
- Предоставляет функцию `create_tables()` для создания всех таблиц
- Позволяет создавать таблицы автоматически при запуске приложения
- Проверяет схему базы данных на соответствие моделям

**Как работает**:
- При запуске приложения вызывается функция `create_tables()`
- Функция проверяет наличие всех необходимых таблиц и создает отсутствующие
- Если таблицы уже существуют, операция не затрагивает существующие данные
- Перед созданием таблиц выполняется проверка соединения с базой данных

**Журналирование**:
- Логирование процесса создания таблиц
- Отчеты об ошибках при создании таблиц
- Информация об успешном создании таблиц

### 4. init_db.py

**Назначение**: Инициализация базы данных начальными данными.

**Функциональность**:
- Заполнение таблиц начальными данными (например, темы новостей, пользователь-администратор)
- Предоставляет функцию `init_db()` для первоначальной настройки базы данных
- Реализует проверку на повторную инициализацию для избежания дублирования данных
- Загружает начальные данные из конфигурационных файлов

**Источники начальных данных**:
- Константы из кода для базовых настроек

**Когда использовать**:
- При первом запуске приложения на новом сервере
- После миграции базы данных
- При развертывании в тестовой или демонстрационной среде

## Используемые технологии

- **SQLAlchemy**: ORM (Object Relational Mapper) для работы с базой данных
- **Pydantic**: Для валидации данных
- **FastAPI**: Для интеграции с API через зависимости
- **psycopg2**: Драйвер для PostgreSQL
- **SQLite3**: Встроенная поддержка для SQLite

## Поддерживаемые базы данных

Модуль конфигурируется для работы с различными СУБД:

1. **PostgreSQL** (рекомендуется для продакшена)
   - Требует указания параметров подключения в переменных окружения
   - Поддерживает полнотекстовый поиск и сложные запросы
   - Обеспечивает высокую производительность и масштабируемость

2. **SQLite** (используется по умолчанию для разработки)
   - Не требует дополнительной настройки
   - Хранит данные в файле `news_digest.db`
   - Ограничения по конкурентному доступу

## Примечания по развертыванию

1. Для продакшн-окружения рекомендуется использовать PostgreSQL вместо SQLite
2. Убедитесь, что соответствующие переменные окружения для базы данных заданы в `.env` файле
3. При миграции базы данных сохраняйте резервные копии данных
4. При масштабировании приложения рекомендуется использовать пул соединений с базой данных
5. Для защиты чувствительных данных в базе данных используйте шифрование полей при необходимости
6. Перед обновлением схемы БД в продакшене всегда тестируйте миграции на тестовой среде
7. Настройте регулярное резервное копирование базы данных
8. При больших объемах данных рассмотрите возможность архивации старых записей
