# Документация модуля api

## Описание

Модуль `api` отвечает за обработку HTTP-запросов и предоставление API-интерфейса для взаимодействия с системой. Он реализован с использованием FastAPI и обеспечивает маршрутизацию запросов, валидацию входящих данных, авторизацию и доступ к бизнес-логике приложения.

## Структура модуля

### 1. api_v1/api.py

**Назначение**: Основной файл, который объединяет все маршруты API.

**Функциональность**:
- Регистрирует все роутеры эндпоинтов
- Определяет префиксы для групп эндпоинтов
- Обеспечивает версионирование API (v1)
- Подключает глобальные зависимости и middleware

**Пример регистрации роутера**:
```python
from fastapi import APIRouter
from app.api.api_v1.endpoints import auth, topics, articles, digests

api_router = APIRouter()
api_router.include_router(auth.router, prefix="/auth", tags=["authentication"])
api_router.include_router(topics.router, prefix="/topics", tags=["topics"])
api_router.include_router(articles.router, prefix="/articles", tags=["articles"])
api_router.include_router(digests.router, prefix="/digests", tags=["digests"])
```

### 2. Эндпоинты (api_v1/endpoints/)

Каждый файл в директории `endpoints` отвечает за определенную группу функциональности:

#### 2.1. auth.py

**Назначение**: Аутентификация и авторизация пользователей.

**Основные эндпоинты**:
- `POST /auth/register` - регистрация нового пользователя
- `POST /auth/login` - аутентификация пользователя и выдача JWT-токена
- `GET /auth/profile` - получение профиля текущего пользователя
- `PUT /auth/profile` - обновление профиля пользователя
- `POST /auth/refresh` - обновление JWT-токена
- `POST /auth/reset-password/request` - запрос на сброс пароля
- `POST /auth/reset-password/confirm` - подтверждение сброса пароля

**Особенности**:
- Использует JWT для аутентификации
- Интегрируется с OAuth2 для стандартного flow авторизации
- Реализует хэширование паролей и безопасное хранение учетных данных
- Поддерживает refresh-токены для продления сессии
- Проверяет сложность паролей

**Пример аутентификации**:
```python
@router.post("/login", response_model=schemas.Token)
def login(
    db: Session = Depends(get_db),
    form_data: OAuth2PasswordRequestForm = Depends()
):
    user = authenticate_user(db, form_data.username, form_data.password)
    if not user:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Incorrect username or password",
            headers={"WWW-Authenticate": "Bearer"},
        )
    access_token = create_access_token(data={"sub": user.email})
    return {"access_token": access_token, "token_type": "bearer"}
```

- `GET /topics/{topic_id}/subscribers` - получение списка подписчиков
- `GET /topics/trending` - получение списка популярных тем
- `GET /topics/recommended` - получение персонализированных рекомендаций

**Особенности**:

#### 2.3. articles.py

**Назначение**: Управление статьями и новостями.

**Основные эндпоинты**:
- `GET /articles/` - получение списка статей с фильтрацией
- `GET /articles/{article_id}` - получение информации о конкретной статье
- `GET /articles/by-topic/{topic_id}` - получение статей по теме
- `POST /articles/` - добавление новой статьи (обычно используется только системой)
- `PUT /articles/{article_id}` - обновление статьи
- `DELETE /articles/{article_id}` - удаление статьи
- `GET /articles/search` - полнотекстовый поиск по статьям
- `GET /articles/popular` - получение популярных статей
- `POST /articles/{article_id}/read` - отметить статью как прочитанную
- `POST /articles/{article_id}/analyze` - запуск анализа статьи

**Особенности**:
- Расширенная фильтрация (по дате, источнику, теме и т.д.)
- Пагинация результатов
- Полнотекстовый поиск
- Трекинг активности чтения
- Сортировка по различным критериям (новизна, популярность, релевантность)

**Пример использования фильтров**:
```python
@router.get("/", response_model=List[schemas.Article])
def read_articles(
    db: Session = Depends(get_db),
    skip: int = 0,
    limit: int = 100,
    topic_id: Optional[int] = None,
    source: Optional[str] = None,
    start_date: Optional[datetime] = None,
    end_date: Optional[datetime] = None,
    sentiment: Optional[str] = None,
    current_user: models.User = Depends(get_current_active_user),
):
    """
    Получение списка статей с фильтрацией по различным параметрам.
    """
    return crud.article.get_multi(
        db, 
        skip=skip, 
        limit=limit,
        topic_id=topic_id,
        source=source,
        start_date=start_date,
        end_date=end_date,
        sentiment=sentiment
    )
```

### 3. deps.py

**Назначение**: Определение зависимостей для внедрения в эндпоинты.

**Основные зависимости**:
- `get_db()` - получение сессии базы данных
- `get_current_user()` - получение текущего аутентифицированного пользователя
- `get_current_active_user()` - получение активного пользователя
- `get_current_superuser()` - получение пользователя с правами админа
- `get_token_data()` - декодирование и валидация JWT-токена
- `get_cache()` - получение кэш-клиента
- `get_rate_limiter()` - получение ограничителя частоты запросов

**Пример зависимости**:
```python
def get_current_user(
    db: Session = Depends(get_db), 
    token: str = Depends(oauth2_scheme)
) -> models.User:
    credentials_exception = HTTPException(
        status_code=status.HTTP_401_UNAUTHORIZED,
        detail="Could not validate credentials",
        headers={"WWW-Authenticate": "Bearer"},
    )
    try:
        payload = jwt.decode(
            token, settings.SECRET_KEY, algorithms=[settings.ALGORITHM]
        )
        username: str = payload.get("sub")
        if username is None:
            raise credentials_exception
        token_data = schemas.TokenData(username=username)
    except JWTError:
        raise credentials_exception
    user = crud.user.get_by_email(db, email=token_data.username)
    if user is None:
        raise credentials_exception
    return user
```

## Механизмы безопасности и авторизации

1. **Аутентификация**:
   - Использование JWT-токенов для авторизации пользователей
   - Проверка токена через зависимость `get_current_user`
   - Различные уровни прав доступа (обычный пользователь, суперпользователь)
   - Механизм refresh-токенов для продления сессии
   - Контроль срока действия токенов

2. **Защита эндпоинтов**:
   - Проверка прав на выполнение действий
   - Ограничение доступа к административным функциям
   - Валидация входящих данных на уровне Pydantic-моделей
   - Защита от CSRF-атак
   - Проверка источника запроса (CORS)

3. **Обработка ошибок**:
   - Стандартизированные ответы об ошибках
   - HTTP-статус коды, соответствующие типу ошибки
   - Детальные сообщения для клиента
   - Логирование ошибок для отладки
   - Обработка непредвиденных исключений

4. **Ограничение частоты запросов (Rate Limiting)**:
   - Лимитирование количества запросов с одного IP-адреса
   - Различные ограничения для разных эндпоинтов
   - Блокировка при превышении лимита
   - Настраиваемые окна времени для ограничений
   
   ```python
   @router.get("/articles/", dependencies=[Depends(RateLimiter(times=100, seconds=60))])
   def get_articles():
       # Эндпоинт ограничен 100 запросами в минуту с одного IP
       ...
   ```

## Документация API

### 1. OpenAPI спецификация

Модуль API автоматически генерирует OpenAPI документацию с использованием встроенных возможностей FastAPI:

- Доступна по URL `/docs` или `/redoc`
- Содержит полное описание всех эндпоинтов
- Показывает схемы запросов и ответов
- Позволяет интерактивно тестировать API

**Настройка OpenAPI**:

```python
app = FastAPI(
    title="AI News Digest API",
    description="API для агрегации новостей с NLP-обработкой",
    version="1.0.0",
    docs_url="/docs",
    redoc_url="/redoc",
    openapi_url="/openapi.json",
)
```

## Взаимодействие с другими модулями

- **models**: Доступ к моделям данных через SQLAlchemy
- **schemas**: Использование Pydantic-моделей для валидации данных
- **services**: Взаимодействие с бизнес-логикой для обработки запросов
- **core**: Использование конфигурации, механизмов безопасности и кэширования
- **db**: Доступ к базе данных через зависимость `get_db`
- **tasks**: Запуск асинхронных задач через Celery

## Обработка ошибок

### 1. Общий механизм

В API реализован стандартный механизм обработки ошибок с использованием FastAPI:

```python
@app.exception_handler(HTTPException)
async def http_exception_handler(request, exc):
    return JSONResponse(
        status_code=exc.status_code,
        content={"detail": exc.detail},
    )

@app.exception_handler(RequestValidationError)
async def validation_exception_handler(request, exc):
    return JSONResponse(
        status_code=status.HTTP_422_UNPROCESSABLE_ENTITY,
        content={"detail": jsonable_encoder(exc.errors())},
    )
```

### 2. Пользовательские исключения

Для бизнес-логики определены специальные исключения:

```python
class NotFoundError(HTTPException):
    def __init__(self, detail: str):
        super().__init__(status_code=404, detail=detail)

class PermissionDeniedError(HTTPException):
    def __init__(self, detail: str = "Permission denied"):
        super().__init__(status_code=403, detail=detail)
```

### 3. Логирование ошибок

Все ошибки логируются для последующего анализа:

```python
@app.exception_handler(Exception)
async def general_exception_handler(request, exc):
    logger.error(f"Unexpected error: {exc}", exc_info=True)
    return JSONResponse(
        status_code=500,
        content={"detail": "Internal server error"},
    )
```

## Примечания по использованию и расширению

1. **Версионирование API**:
   - При внесении несовместимых изменений создавайте новую версию API (v2)
   - Используйте отдельные пространства имен для разных версий
   - Поддерживайте обратную совместимость как можно дольше
   - Документируйте изменения в API между версиями

2. **Добавление новых эндпоинтов**:
   - Создайте новый файл в `endpoints` или добавьте функцию в существующий
   - Зарегистрируйте роутер в `api.py` для включения в API
   - Следуйте принципам REST при проектировании эндпоинтов
   - Используйте правильные HTTP-методы (GET, POST, PUT, DELETE)

3. **Производительность**:
   - Используйте кэширование для часто запрашиваемых данных
   - Применяйте пагинацию и фильтрацию для больших наборов данных
   - Оптимизируйте запросы к базе данных
   - Мониторьте время отклика эндпоинтов
   - Используйте асинхронные эндпоинты для IO-bound операций

4. **Тестирование API**:
   - Напишите модульные тесты для каждого эндпоинта
   - Используйте pytest и pytest-asyncio для тестирования
   - Создайте фикстуры для тестовых данных
   - Тестируйте граничные случаи и обработку ошибок
   - Используйте mock-объекты для имитации внешних сервисов
