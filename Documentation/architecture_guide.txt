# Архитектура проекта AI News Digest Aggregator: подробное описание модулей

## Общая структура проекта

Проект представляет собой систему агрегации новостей с интеллектуальной обработкой:
1. Собирает новостные статьи из различных источников
2. Анализирует их содержимое с помощью NLP (обработки естественного языка)
3. Формирует персонализированные дайджесты для пользователей

## Основные модули бэкенда

### 1. База данных (models/models.py)

#### Назначение:
Хранение всех данных: пользователей, тем, статей, дайджестов.

#### Основные модели:
- **User**: Информация о пользователях системы
  - Хранит регистрационные данные, подписки на темы
  - Связан с дайджестами, которые создаются для него

- **Topic**: Темы новостей
  - Каждая тема имеет название, описание, категорию
  - Пользователи могут подписываться на интересующие темы

- **Article**: Статьи, полученные из разных источников
  - Содержит заголовок, текст, URL источника
  - Хранит результаты NLP анализа (тональность, ключевые слова, сущности)
  - Привязан к определенной теме

- **Digest**: Сформированные дайджесты для пользователей
  - Объединяет отобранные статьи для конкретного пользователя
  - Отслеживает статус прочтения

- **DigestArticle**: Связующая таблица между дайджестами и статьями
  - Определяет порядок статей в дайджесте

### 2. Web-сервер (main.py, api/)

#### Назначение:
Предоставляет API для работы с системой через HTTP-запросы.

#### Основные компоненты:
- **main.py**: Точка входа и настройка FastAPI сервера
  - Настраивает CORS (доступ с разных источников)
  - Подключает все маршруты API
  - Запускает сервер на указанном порту

- **api_v1/api.py**: Маршрутизатор API запросов
  - Объединяет все эндпоинты API под единым префиксом /api/v1
  - Направляет запросы к соответствующим обработчикам

- **api_v1/endpoints/**: Папка с отдельными модулями API
  - **users.py**: Регистрация, авторизация, управление пользователями
  - **topics.py**: CRUD операции для тем
  - **articles.py**: Поиск и получение статей
  - **digests.py**: Управление дайджестами

### 3. Сбор новостей (services/news_scraper.py)

#### Назначение:
Собирает новостные статьи с различных веб-сайтов методом скрапинга.

#### Как работает:
1. **NewsSource**: Класс для хранения настроек источника
   - Содержит URL, CSS-селекторы для извлечения данных
   - Настраивается для каждого новостного сайта индивидуально

2. **NewsScraper**: Основной класс для скрапинга
   - **_initialize_sources()**: Настраивает все источники новостей
   - **scrape_source()**: Обрабатывает один источник
     - Выполняет HTTP-запрос к новостному сайту
     - Извлекает список статей с помощью BeautifulSoup и CSS-селекторов
     - Сохраняет найденные статьи в базу данных
   - **scrape_all_sources()**: Обрабатывает все источники для указанной темы
   - **scrape_for_all_topics()**: Запускает сбор новостей для всех тем

3. **Особенности реализации**:
   - Случайная задержка между запросами для избежания блокировки
   - Ротация User-Agent заголовков
   - Обработка ошибок и повторные попытки
   - Проверка наличия дубликатов статей перед сохранением

### 4. Агрегатор новостей через API (services/news_aggregator.py)

#### Назначение:
Получает статьи от новостных API (NewsAPI, NYTimes API).

#### Как работает:
1. **NewsAggregator**: Собирает новости через API
   - **fetch_news_api()**: Получает новости с NewsAPI.org
   - **fetch_nytimes()**: Получает новости с API New York Times
   - **process_articles()**: Обрабатывает и сохраняет статьи в БД
   - **aggregate_news()**: Основной метод, запускающий сбор из всех источников

2. **Особенности**:
   - Использует асинхронные запросы (aiohttp) для параллельного получения данных
   - Проверяет наличие API ключей перед выполнением запросов
   - Извлекает полный текст статей при необходимости

### 5. NLP анализатор (services/nlp_analyzer.py)

#### Назначение:
Выполняет интеллектуальный анализ текста статей для улучшения поиска и группировки.

#### Основные функции:
1. **NLPAnalyzer**: Основной класс анализа
   - **analyze_sentiment()**: Определяет тональность статьи (позитивная/негативная)
   - **extract_entities()**: Извлекает именованные сущности (люди, организации, места)
   - **extract_keywords()**: Выделяет ключевые слова для поиска
   - **extract_key_phrases()**: Выделяет ключевые фразы/утверждения
   - **generate_summary()**: Создает краткое содержание статьи
   - **process_unanalyzed_articles()**: Обрабатывает все статьи без анализа

2. **Используемые технологии**:
   - spaCy: Библиотека для глубокого анализа текста
   - TextBlob: Анализ тональности и субъективности
   - NLTK: Дополнительные функции обработки текста

### 6. Генератор дайджестов (services/digest_generator.py)

#### Назначение:
Создает персонализированные дайджесты на основе интересов пользователей.

#### Как работает:
1. **DigestGenerator**: Основной класс для генерации дайджестов
   - **get_user_topics()**: Получает темы, на которые подписан пользователь
   - **get_recent_articles()**: Находит недавние статьи по выбранным темам
   - **rank_articles()**: Ранжирует статьи по релевантности для пользователя
   - **create_digest()**: Создает дайджест для конкретного пользователя
   - **generate_digests_for_all_users()**: Запускает генерацию для всех пользователей

2. **Алгоритм отбора статей**:
   - Приоритет отдается статьям с высоким рейтингом по теме
   - Учитывается тональность и актуальность
   - Группировка по темам и исключение дубликатов

### 7. Фоновые задачи (tasks/news_tasks.py, core/celery_app.py)

#### Назначение:
Выполняет регулярные операции в фоновом режиме.

#### Основные компоненты:
1. **celery_app.py**: Настройка Celery для фоновых задач
   - Проверяет доступность Redis
   - Настраивает альтернативные бэкенды при необходимости

2. **news_tasks.py**: Задачи, выполняемые по расписанию
   - **aggregate_news()**: Запускает сбор новостей через API раз в час
   - **analyze_articles()**: Запускает анализ статей каждые 30 минут
   - **generate_digests()**: Создает дайджесты ежедневно
   - **scrape_news()**: Запускает скрапинг новостей каждые 3 часа

3. **Преимущества использования Celery**:
   - Надежное выполнение длительных операций
   - Автоматический перезапуск при ошибках
   - Планирование по расписанию
   - Возможность масштабирования на несколько серверов

### 8. Управление сессиями БД (db/session.py)

#### Назначение:
Обеспечивает подключение к базе данных и управление сессиями.

#### Компоненты:
- **engine**: Создает подключение к БД на основе настроек
- **SessionLocal**: Фабрика сессий для работы с БД
- **get_db()**: Зависимость для FastAPI, предоставляющая доступ к БД

### 9. Безопасность (core/security.py)

#### Назначение:
Обеспечивает аутентификацию и авторизацию пользователей.

#### Основные функции:
- **verify_password()**: Проверяет пароль пользователя
- **get_password_hash()**: Создает безопасный хеш пароля
- **create_access_token()**: Создает JWT токен для авторизации
- **get_current_user()**: Получает текущего пользователя по токену

### 10. Кэширование (core/cache.py)

#### Назначение:
Кэширует часто запрашиваемые данные для ускорения работы.

#### Основные компоненты:
- **RedisCache**: Реализация кэша с использованием Redis
- **SqliteCache**: Альтернативный кэш для работы без Redis
- **get_cache()**: Получает подходящую реализацию кэша
- Декораторы для автоматического кэширования функций

## Как всё работает вместе

### Поток данных:
1. **Сбор данных**:
   - Периодически запускаются фоновые задачи (Celery)
   - Скраперы и API-клиенты получают статьи
   - Статьи сохраняются в базу данных

2. **Обработка данных**:
   - NLP-анализатор обрабатывает новые статьи
   - Извлекает ключевые слова, сущности, тональность
   - Обновляет метаданные в базе данных

3. **Доставка информации**:
   - Генератор дайджестов создает персонализированные подборки
   - API предоставляет доступ к данным через HTTP
   - Пользователи получают информацию через веб-интерфейс

### Масштабируемость:
- Модульная архитектура позволяет добавлять новые источники
- Celery обеспечивает распределение нагрузки между серверами
- Кэширование снижает нагрузку на базу данных

## Технические детали и зависимости

### Основные библиотеки:
- **FastAPI**: Современный веб-фреймворк для API
- **SQLAlchemy**: ORM для работы с базой данных
- **Pydantic**: Валидация данных и сериализация
- **Celery**: Система фоновых задач и планировщик
- **spaCy и NLTK**: Библиотеки для NLP анализа
- **BeautifulSoup**: Парсинг HTML для скрапинга
- **Redis**: Хранилище для кэша и брокер сообщений
- **Requests/aiohttp**: HTTP-клиенты для API

### Порядок запуска компонентов:
1. База данных (SQLite или PostgreSQL)
2. Redis (опционально)
3. FastAPI веб-сервер
4. Celery worker для фоновых задач
5. Celery beat для планировщика
