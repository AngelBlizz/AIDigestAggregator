# Документация модуля tasks

## Описание

Модуль `tasks` содержит определения задач для асинхронной и периодической обработки с использованием Celery. Этот модуль позволяет выполнять длительные или ресурсоемкие операции в фоновом режиме, не блокируя основные запросы API. Кроме того, он управляет регулярным выполнением задач по расписанию, таких как сбор новостей или генерация дайджестов.

## Структура модуля

### news_tasks.py

**Назначение**: Определяет задачи, связанные со сбором, обработкой новостей и генерацией дайджестов.

**Основные задачи**:

#### 1. aggregate_news

**Функциональность**: Агрегация новостей из различных источников.

```python
@shared_task
def aggregate_news():
    """Задача для агрегации новостей из различных источников"""
    db = SessionLocal()
    try:
        aggregator = NewsAggregator(db)
        aggregator.aggregate_news()
    finally:
        db.close()
```

**Особенности**:
- Использует сервис `NewsAggregator` для сбора новостей
- Автоматически закрывает соединение с базой данных после выполнения
- Выполняется периодически по расписанию (каждый час)

#### 2. analyze_articles

**Функциональность**: NLP-анализ собранных статей.

```python
@shared_task
def analyze_articles():
    """Задача для анализа необработанных статей"""
    db = SessionLocal()
    try:
        analyzer = NLPAnalyzer(db)
        analyzer.process_unanalyzed_articles()
    finally:
        db.close()
```

**Особенности**:
- Использует сервис `NLPAnalyzer` для анализа статей
- Обрабатывает только непроанализированные ранее статьи
- Выполняется периодически по расписанию (каждые 30 минут)

#### 3. generate_digests

**Функциональность**: Создание персонализированных дайджестов.

```python
@shared_task
def generate_digests():
    """Задача для генерации дайджестов для всех пользователей"""
    db = SessionLocal()
    try:
        generator = DigestGenerator(db)
        generator.generate_digests_for_all_users()
    finally:
        db.close()
```

**Особенности**:
- Использует сервис `DigestGenerator` для создания дайджестов
- Генерирует дайджесты для всех активных пользователей
- Выполняется периодически по расписанию (ежедневно в 8:00)

#### 4. scrape_news

**Функциональность**: Скрапинг новостей из настроенных источников.

```python
@shared_task
def scrape_news():
    """Задача для скрапинга новостей из настроенных источников"""
    db = SessionLocal()
    try:
        logger.info("Запуск запланированной задачи по скрапингу новостей")
        scraper = NewsScraper(db)
        results = scraper.scrape_for_all_topics()
        
        total_articles = sum(results.values())
        logger.info(f"Скрапинг {total_articles} статей из всех источников")
        
        # Если мы нашли новые статьи, также запустите анализ
        if total_articles > 0:
            analyzer = NLPAnalyzer(db)
            analyzer.process_unanalyzed_articles()
            logger.info("Завершено аналитическое исследование новых собранных статей")
            
        return results
    except Exception as e:
        logger.error(f"Ошибка в задаче по скрапингу новостей: {str(e)}")
        raise
    finally:
        db.close()
```

**Особенности**:
- Использует сервис `NewsScraper` для сбора новостей
- Автоматически запускает анализ для новых статей
- Содержит обработку ошибок и логирование
- Выполняется периодически по расписанию (каждые 3 часа)

## Расписание задач

Расписание периодических задач настраивается в функции `configure_periodic_tasks`:

```python
from celery.schedules import crontab

# Настройка периодических задач
def configure_periodic_tasks(sender, **kwargs):
    # Агрегировать новости каждый час
    sender.add_periodic_task(
        crontab(minute=0),
        aggregate_news.s(),
        name='aggregate-news-hourly'
    )
    
    # Анализировать статьи каждые 30 минут
    sender.add_periodic_task(
        crontab(minute='*/30'),
        analyze_articles.s(),
        name='analyze-articles-every-30-min'
    )
    
    # Генерировать дайджесты ежедневно в 8:00
    sender.add_periodic_task(
        crontab(hour=8, minute=0),
        generate_digests.s(),
        name='generate-daily-digests'
    )
    
    # Скрапинг новостей каждые 3 часа
    sender.add_periodic_task(
        crontab(minute=0, hour='*/3'),
        scrape_news.s(),
        name='scrape-news-every-3-hours'
    )
```

Используется синтаксис `crontab` для гибкого планирования задач:
- `minute=0` - запуск в начале каждого часа
- `minute='*/30'` - запуск каждые 30 минут
- `hour=8, minute=0` - запуск в 8:00
- `minute=0, hour='*/3'` - запуск каждые 3 часа

## Взаимодействие с другими модулями

### Взаимодействие с core
- Использует конфигурацию Celery из `core/celery_app.py`
- Применяет настройки логирования

### Взаимодействие с services
- Вызывает методы из сервисных классов для выполнения бизнес-логики
- Используется с `NewsAggregator`, `NLPAnalyzer`, `DigestGenerator` и `NewsScraper`

### Взаимодействие с models
- Получает данные из базы данных через SQLAlchemy сессию
- Сохраняет результаты выполнения задач в базу данных

## Примечания по использованию

### Запуск Celery Worker
Для запуска обработчика Celery используйте следующую команду:

```bash
celery -A app.core.celery_app worker --loglevel=info
```

### Запуск Celery Beat (планировщик)
Для запуска планировщика периодических задач:

```bash
celery -A app.core.celery_app beat --loglevel=info
```

### Ручной запуск задачи
Чтобы запустить задачу вручную из кода:

```python
from app.tasks.news_tasks import scrape_news

# Запуск задачи асинхронно
task = scrape_news.delay()

# Получение результата задачи
result = task.get()
```

### Мониторинг задач
Для мониторинга выполнения задач можно использовать Flower - веб-интерфейс для Celery:

```bash
celery -A app.core.celery_app flower --port=5555
```

Через интерфейс Flower можно:
- Просматривать активные задачи
- Проверять статус выполнения
- Просматривать журналы ошибок
- Следить за производительностью системы
