# Документация модуля core

## Описание

Модуль `core` является центральным компонентом бэкенд-системы, содержащим базовые конфигурации, механизмы безопасности и инфраструктурные элементы, необходимые для работы всего приложения. Этот модуль представляет собой фундамент, на котором строятся остальные компоненты системы.

## Структура модуля

### 1. config.py

**Назначение**: Содержит централизованную конфигурацию всего приложения.

**Функциональность**:
- Загружает переменные окружения из `.env` файла
- Определяет класс `Settings` с настройками приложения, включая:
  - Базовые настройки приложения (название, версия, API префикс)
  - Настройки окружения (разработка, продакшн)
  - Параметры подключения к базе данных
  - Настройки безопасности и JWT-токенов
  - Конфигурация источников новостей и API-ключи
  - Настройки для Celery (обработки задач)
  - Конфигурация NLP-моделей
  - Настройки кэширования

**Ключевые методы класса Settings**:
- `get_database_url()` - формирует URL для подключения к БД на основе настроек
- `get_cache_url()` - возвращает URL для подключения к Redis
- `is_development()` - проверяет, является ли текущее окружение средой разработки

**Как использовать**:
```python
from app.core.config import settings

# Использовать настройки
api_prefix = settings.API_V1_STR
jwt_algorithm = settings.JWT_ALGORITHM
```

### 2. security.py

**Назначение**: Обеспечивает функциональность аутентификации и авторизации.

**Функциональность**:
- Хэширование и верификация паролей с использованием bcrypt
- Создание и проверка JWT-токенов
- Получение текущего пользователя из JWT-токена
- Проверка прав суперпользователя

**Ключевые функции**:
- `create_access_token()` - создаёт JWT-токен доступа
- `verify_password()` - проверяет пароль против хэша
- `get_password_hash()` - создаёт хэш пароля
- `get_current_user()` - получает пользователя из токена
- `get_current_active_superuser()` - проверяет права суперпользователя
- `decode_token()` - декодирует JWT-токен и проверяет его валидность

**Обработка ошибок аутентификации**:
- `TokenExpiredError` - ошибка при истечении срока действия токена
- `JWTError` - общая ошибка при проблемах с JWT
- `CredentialsException` - исключение при недостаточных правах

### 3. celery_app.py

**Назначение**: Настраивает и инициализирует Celery для асинхронной обработки задач.

**Функциональность**:
- Создание экземпляра Celery и его конфигурирование
- Настройка периодических задач для сбора новостей
- Конфигурация брокера сообщений (Redis)
- Обработка ошибок при недоступности Redis
- Настройка альтернативных бэкендов при необходимости

**Как использовать**:
```python
from app.core.celery_app import celery_app

# Регистрация задачи
@celery_app.task
def my_task():
    pass
```

### 4. cache.py

**Назначение**: Предоставляет механизм кэширования для оптимизации производительности.

**Функциональность**:
- Интерфейс для работы с Redis как кэшем
- Декораторы для кэширования результатов функций
- Настройка TTL (времени жизни) для кэшированных данных
- Инвалидация кэша при обновлении данных
- Фоллбэк на локальное кэширование при недоступности Redis

**Ключевые функции**:
- `cache_response()` - декоратор для кэширования ответов API
- `invalidate_cache()` - инвалидирует кэш по ключу
- `clear_all_cache()` - очищает весь кэш
- `get_cache()` - получает подходящую реализацию кэша
- `memoize()` - функциональный декоратор для кэширования результатов функций

## Важные зависимости

- **python-jose**: Для работы с JWT-токенами
- **passlib**: Для хэширования паролей
- **python-dotenv**: Для загрузки переменных окружения
- **redis**: Для кэширования и брокера сообщений
- **celery**: Для асинхронной обработки задач
- **starlette**: Для промежуточного ПО и CORS
- **uvicorn**: ASGI-сервер для запуска приложения

## Примечания по развертыванию

1. В продакшн-окружении всегда используйте сложный `SECRET_KEY` для JWT-токенов
2. Рекомендуется настроить более короткое время жизни токенов (ACCESS_TOKEN_EXPIRE_MINUTES) в продакшене
3. Убедитесь, что Redis настроен правильно и защищен паролем в продакшн-среде
4. Для наилучшей производительности рекомендуется использовать Redis как для кэширования, так и для Celery
5. Используйте переменные окружения для хранения чувствительных данных, а не хардкодьте их
6. При масштабировании приложения рекомендуется использовать несколько экземпляров Celery worker
7. Настройте механизм ротации и архивации логов для долгосрочного хранения
