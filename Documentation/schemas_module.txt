# Документация модуля schemas

## Описание

Модуль `schemas` содержит Pydantic-модели, используемые для валидации, сериализации и десериализации данных в API. Эти схемы определяют структуру входящих и исходящих данных для эндпоинтов и обеспечивают автоматическую документацию API через Swagger/OpenAPI.

## Основные компоненты

### 1. user.py

**Назначение**: Схемы для работы с пользователями и аутентификации.

**Основные схемы**:
- `UserBase`: Базовая схема с общими полями пользователя
- `UserCreate`: Схема для создания пользователя (включает пароль)
- `UserUpdate`: Схема для обновления пользователя (все поля опциональны)
- `UserResponse`: Схема для ответа API с данными пользователя
- `UserInDB`: Внутренняя схема, включающая хэшированный пароль
- `Token`: Схема для JWT-токена
- `TokenPayload`: Схема для данных внутри JWT-токена
- `AuthResponse`: Схема для ответа при аутентификации (включает токен и данные пользователя)

**Особенности**:
- Использование `EmailStr` для валидации email
- Наследование моделей для уменьшения дублирования кода
- Исключение чувствительных данных (пароль) из ответов API

### 2. topic.py

**Назначение**: Схемы для работы с темами новостей.

**Основные схемы**:
- `TopicBase`: Базовая схема с общими полями темы
- `TopicCreate`: Схема для создания темы
- `TopicUpdate`: Схема для обновления темы
- `TopicResponse`: Схема для ответа API с данными о теме

**Поля**:
- `id`: ID темы (только в ответах)
- `name`: Название темы
- `description`: Описание темы
- `category`: Категория темы
- `is_selected`: Флаг, указывающий выбрана ли тема пользователем (опционально)

### 3. source.py

**Назначение**: Схемы для работы с источниками новостей.

**Основные схемы**:
- `SourceBase`: Базовая схема источника новостей
- `SourceCreate`: Схема для добавления нового источника
- `SourceUpdate`: Схема для обновления источника
- `SourceResponse`: Схема для ответа API с данными об источнике новостей

**Поля**:
- `id`: ID источника (только в ответах)
- `name`: Название источника
- `url`: URL источника
- `description`: Описание источника
- `logo_url`: URL логотипа источника
- `is_active`: Флаг активности источника

### 4. digest.py

**Назначение**: Схемы для работы с дайджестами новостей.

**Основные схемы**:
- `ArticleBrief`: Краткая информация о статье в дайджесте
- `DigestCreate`: Схема для создания дайджеста
- `DigestUpdate`: Схема для обновления дайджеста
- `DigestResponse`: Схема для ответа API с данными о дайджесте
- `DigestArticleCreate`: Схема для добавления статьи в дайджест
- `DigestWithArticles`: Расширенная схема дайджеста со списком статей

**Особенности**:
- Вложенные модели для представления статей в дайджесте
- Различные уровни детализации для разных эндпоинтов
- Специальные схемы для управления статьями в дайджесте

### 5. analytics.py

**Назначение**: Схемы для аналитических данных и NLP-анализа.

**Основные схемы**:
- `SentimentAnalysis`: Схема для результатов анализа тональности
- `EntityAnalysis`: Схема для результатов анализа именованных сущностей
- `KeywordAnalysis`: Схема для результатов анализа ключевых слов
- `ArticleAnalytics`: Полная аналитика по статье
- `TopicTrend`: Схема для трендов по теме

**Особенности**:
- Сложные вложенные структуры для представления аналитических данных
- Поддержка различных форматов временных рядов
- Специализированные поля для NLP-результатов

## Взаимодействие со слоем API

Схемы используются в API эндпоинтах следующим образом:

1. **Входные данные**:
   ```python
   @router.post("/users/", response_model=UserResponse)
   def create_user(user: UserCreate, db: Session = Depends(get_db)):
       # Создание пользователя на основе валидированных данных
   ```

2. **Выходные данные**:
   ```python
   @router.get("/topics/{topic_id}", response_model=TopicResponse)
   def get_topic(topic_id: int, db: Session = Depends(get_db)):
       # Возврат данных, которые будут сериализованы в TopicResponse
   ```

3. **Валидация запросов**:
   ```python
   @router.put("/digests/{digest_id}", response_model=DigestResponse)
   def update_digest(
       digest_id: int, 
       digest_update: DigestUpdate, 
       db: Session = Depends(get_db)
   ):
       # Обновление дайджеста на основе валидированных данных
   ```

## Ключевые возможности Pydantic-моделей

- **Автоматическая валидация типов** и ограничений
- **Преобразование данных** (например, строк в datetime)
- **Документация API** через интеграцию с OpenAPI
- **Настраиваемые валидаторы** для сложной бизнес-логики
- **Наследование моделей** для эффективного переиспользования кода

## Примечания по разработке

1. При добавлении новых полей в модели базы данных не забудьте обновить соответствующие Pydantic-схемы
2. Используйте `Config.from_attributes = True` для моделей, которые должны преобразовываться из ORM-объектов
3. Разделяйте схемы для создания, обновления и ответов для четкого разграничения ответственности
4. Используйте опциональные поля (`Optional[Type]`) для полей, которые не обязательны или могут изменяться
5. Добавляйте описания полей через аннотации для улучшения документации API
